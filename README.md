# BMW Experience

BMW Experience is an independent, interactive 3D performance-car product concept
built with Vite, React, TypeScript, React Three Fiber, Three.js, and Tailwind
CSS. It is not affiliated with, endorsed by, or produced by BMW AG.

## Product surface

- Immersive, scroll-led experience with a fixed 3D vehicle stage.
- Vehicle exploration with hotspots, focus views, drag rotation, wheel/pinch
  zoom, and keyboard-accessible view controls.
- Live configuration for body color, wheel/rim color, interior, and trim with an
  estimated concept price.
- Engineering topics, simulated track telemetry, and driving modes.
- Build summary saved to local storage on the current device.
- Graceful loading, WebGL/model failure fallback, retry, reduced-motion support,
  and a no-WebGL content path.

The experience is intentionally a front-end concept: there is no commerce,
account, analytics, or remote configuration service connected.

## Development

Install Node.js and npm, then run:

```sh
npm ci
npm run dev
```

Run the quality gates locally with:

```sh
npm run lint
npx tsc -b
npm run build
```

The production build can be previewed locally with:

```sh
npm run build
npm run preview
```

## Asset and performance notes

The vehicle assets are `public/models/car.glb`, `public/models/car-medium.glb`,
and `public/models/car-low.glb`, with matching KTX2 variants named
`car-ktx2.glb`, `car-medium-ktx2.glb`, and `car-low-ktx2.glb`. They are
web-optimized derivatives of the supplied 2025 BMW M5 Sedan source: geometry is
welded, joined offline, and Meshopt-compressed. Each KTX2 derivative uses ETC1S
Basis Universal only for the texture payload that measured smaller than its
WebP counterpart; the other 32 WebP and 2 PNG payloads remain unchanged. This
per-texture policy avoids increasing transfer size for this model's many small
palette textures while still providing a validated KTX2 path on every tier.
Base-color and emissive maps are tagged sRGB; normal, roughness, metallic and
other data maps remain non-color data.

The high asset keeps the visible vehicle detail without the original export's
900 mesh definitions and 2,453 nodes; the medium and low assets additionally
simplify geometry and cap texture dimensions at 512px and 256px respectively.
All three KTX2 assets carry `customizationGroup` metadata on their 27 mesh
nodes: `Paint_Geo` is BODY, `polySurface148`/`Wheel1A_3D` is RIMS, the four
`Interior*` meshes are INTERIOR, and `Carbon1_Geo` is TRIM. Everything else is
OTHER, including glass, lamps, badges, grilles, tires, brakes and the engine.
The supplied source contains no door/hood/trunk nodes or animation clips, so no
such animation is claimed by the integration. See `public/models/car-license.txt`
for the required attribution and license terms.

The 3D experience is loaded as a deferred chunk so the editorial page can render
without waiting for Three.js. The selected model is requested only after the
device profile is known, so low-end devices never download the high asset. The
profile uses conservative signals from WebGL support/capabilities, logical
cores, device memory, network Save-Data/effective type, touch input, and
viewport size. LOW renders the 2.0 MB asset at DPR 1 and 30fps with no shadows;
MEDIUM renders the 2.7 MB asset at DPR 1.25 and 45fps with one shadowed key
light; HIGH renders the 3.5 MB asset at a capped DPR of 1.5 with the full
studio rig and contact shadow. Demand-rendered tiers pause their invalidation
loop while the page is hidden. Append `?quality=low`, `?quality=medium`, or
`?quality=high` to a development URL to verify a tier manually. Append `&perf`
to print the renderer's FPS, draw calls, triangles, geometry count, texture
count, and pixel ratio to the console.

The tiered assets were generated with glTF Transform 4.5.0's optimize pipeline
using Meshopt compression, offline joining, and geometry simplification for the
medium/low variants. KTX2 derivatives are generated by the pinned
`assets:ktx2` script with glTF Transform 4.5.0 and KTX-Software 4.4.x available
on `PATH` as `ktx`. The script decodes the existing WebP images only in a temp
directory, encodes KTX2, then replaces only image buffer ranges so the original
Meshopt geometry bytes are retained. If the source model changes, regenerate
the variants and verify the material selectors in
`src/components/three/material-classification.ts` before release.

Measured release asset sizes:

| tier   |    WebP GLB |    KTX2 GLB |             KTX2 textures | transfer change |
| ------ | ----------: | ----------: | ------------------------: | --------------: |
| HIGH   | 3,469,128 B | 3,459,964 B | 1 ETC1S + 32 WebP + 2 PNG |           −0.3% |
| MEDIUM | 2,688,436 B | 2,679,272 B | 1 ETC1S + 32 WebP + 2 PNG |           −0.3% |
| LOW    | 2,011,996 B | 2,002,832 B | 1 ETC1S + 32 WebP + 2 PNG |           −0.5% |

KTX2 textures upload as GPU-compressed blocks instead of fully decompressed
RGBA images. The converted 256×256 ETC1S RGBA map therefore has roughly 4×
less backing memory than an RGBA8 mip chain, subject to the driver's selected
transcode target; the remaining WebP maps keep their existing GPU behavior.
`public/basis/` contains the local Three.js r185 Basis transcoder
(`basis_transcoder.js` and `.wasm`) for GitHub Pages; it is requested by
KTX2Loader only when a compressed model is actually loaded. If a KTX2 parse,
transcoder or texture request fails, the runtime logs the error and retries the
matching WebP GLB (`car.glb`, `car-medium.glb`, or `car-low.glb`).

If the model is replaced, review `src/components/three/material-classification.ts`
for its mesh/material selectors and semantic groups.
